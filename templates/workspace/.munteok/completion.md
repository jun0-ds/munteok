# 완료와 보관

사용자가 결과를 확인하고 작업이 끝났다고 판단했을 때 적용한다. 진행 중인 서비스나 프로젝트는 남겨두고
완료된 이슈만 정리한다. 완료의 뜻이 불명확하면 이동 전에 확인한다.

1. 결과 파일을 열거나 검증해 완료 기준과 대조한다. 남은 일이 있으면 기록한다.
2. 원본·편집 파일·재현 코드와 필요한 자료는 남긴다. 자신이 만든 불필요한 임시 파일만 정리한다.
3. 작업 `CONTEXT.md`에 완료 날짜·결과 링크·재개 방법을 적는다.
4. 이동 전에 현재 절대경로와 실제 에이전트 기록 위치를 남긴다. 손맛/scribe 로그가 cwd를 키로 사용하면
   그 이전 cwd와 로그 위치를 기록한다. 존재를 확인하지 못한 기록은 있다고 쓰지 않는다.
5. 같은 영역의 `보관/YYYYMMDD_이름/`으로 옮긴다. 회사별 업무는 그 회사 안의 보관 폴더를 쓴다.
   같은 이름이 있으면 덮지 말고 구분 이름을 정한다. 실행 중인 프로세스나 Git worktree처럼 이동에 민감한
   작업은 중지·경로 영향부터 확인하고 준비되지 않았으면 이동을 보류한다.
6. 내부 상대 링크와 외부에서 들어오는 링크를 확인한다. 상위 활성 목록과 의제에서 제거하고
   보관 위치 및 이전 경로를 연결해 요청 시 다시 찾을 수 있게 한다.
7. 사용자에게 남긴 결과와 보관 위치를 알린다. 보관이 삭제와 다르다는 점도 설명한다.

과거 작업을 재개하면 원래 영역의 활성 폴더로 복원하고 이동 기록·활성 링크를 함께 갱신한다.
